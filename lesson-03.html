秩与方程组：什么时候有解

第 2 课说矩阵是「搬动空间的机器」。这一课问它一个更狠的问题——给一个目标点，机器能不能把它搬过来。

学完你能：把 Ax = b 读成「b 在不在两列的拼法里」；用秩判断方程组是唯一解 / 无解 / 无穷多解；说出秩的三种等价说法；写出通解 x = x_p + t·n；用 numpy 的 matrix_rank 和 lstsq 当场验证。

1先从一个真实问题开始

你在调一杯咖啡：浓缩倒了 x 毫升、牛奶倒了 y 毫升。你手上有两个读数——总重量、总热量——能不能反推出各倒了多少？

两个未知数、两个读数，直觉上够了。写成两条式子：

x + y = 60　　2x + 3y = 150

解出来 x = 30、y = 30。唯一解，两个读数各管一条信息。

但换个情况：假设第二台秤称的其实就是「总重量 × 2」，那两条式子变成：

x + y = 60　　2x + 2y = 120

这两条说的是同一句话。x = 10、y = 50 满足；x = 40、y = 20 也满足。你倒了两杯完全不同的咖啡，读数一模一样。

注意这里发生了什么：系统不是「算不出来」，而是第二个读数没带来任何新信息。
一个系统给不出唯一答案，原因只有两种：读数互相重复（信息不够），或者读数互相矛盾（信息打架）。区分这两种情况的那个数，叫秩。

再补一句现实里的意思：你在做实验、做回归、做传感器融合时，如果两路信号其实在测同一件事，再加一路也不会让结果更确定——这就是「秩不够」。

矩阵 [[a, b], [c, d]]，目标 b = (p, q)。红箭头是第一列 (a, c)，蓝箭头是第二列 (b, d)，绿箭头是目标 b。
多出来的 cond 是条件数：两列有多接近平行。它越大，输入的一点点误差就会被放大成解的一点点巨大偏差——点「近乎平行」，det 只剩 0.02，解直接飞到 (−97, 50)，图上会标「解跑到图外」。这就是「有答案，但别太信」。

列的看法（先看这个）：把 Ax = b 读成

x₁·(第一列) + x₂·(第二列) = b

——你要用两列当配料，按系数 x₁, x₂ 配出一杯正好等于 b 的饮料。配得出来，就有解；配不出来，就无解。两列能配出的所有点的集合，叫列空间。

行的看法：每条方程是一条直线，解就是交点。两条线相交于一点 = 唯一解；两条线平行 = 无解；两条线重合 = 无穷多解。

两种看法是同一件事的两面：行平行 ⟺ 两行成比例 ⟺ 两列也成比例 ⟺ 列空间被压成一条线 ⟺ 秩 < 2。自己拖「近乎平行」那组数看一遍，比背十遍强。

3秩：这个矩阵到底有几个独立方向

秩（rank）的一句话定义：矩阵里真正互相独立的列有几个。不独立的列，只是别人乘个倍数的结果，它带不来新信息。

三种说法完全等价，做题时随便挑最方便的那个：

说法怎么看出来
独立列的个数一列能不能写成其他列的线性组合；能，它就白占位置
列空间的维数两列能配出的点集：整个平面（2 维）还是一条线（1 维）
消元后非零行的个数高斯消元把成比例的方程消掉，剩几行就是几

对 2×2 的矩阵，还有一种最快的算法：看行列式。

det ≠ 0 ⟺ 秩 = 2（满秩）　　det = 0 ⟺ 秩 ≤ 1（亏秩）

第 2 课里 det 的读法是「面积放大几倍」；现在它多了一个读法：det = 0 说明这个变换把平面压扁了，信息丢了，所以回不去——回不去就是不可逆，不可逆就是秩不够。

为什么行列式只对 2×2、3×3 好使：因为方阵才有行列式。真实数据是 1000 行 × 5 列的矩阵，根本没有 det，但秩一直存在。
判断「够不够信息」的通用工具是秩，不是行列式。这也是为什么 numpy 里 matrix_rank 比 det 更常用。

4三种结局，一张表说完

设 A 是 2×2，Ax = b。把所有情况列全，只有三种：

det秩b 在哪结局
≠ 02整个平面里任意一点都够得着唯一解
01b 正好落在那条列空间直线上无穷多解（一维的一整条线）
01b 不在那条直线上无解——只能退而求「最接近」

第三行是整门课后半段的主角：b 落不到列空间里，问题本身就没有精确答案。这时候不是硬凑，而是把 b 投影进去，取投影点对应的解——那就是下一课的最小二乘。

拿一个亏秩的例子算到底

取 A = [[1, 2], [2, 4]]，两列 (1, 2) 和 (2, 4) 是同一方向的，秩 = 1，列空间就是直线 y = 2x。

先试 b = (3, 6)：(3, 6) 正好在 y = 2x 上，所以有解，而且不止一个。numpy 的 solve 会直接报错（矩阵不可逆），lstsq 会还给你一个解 (0.6, 1.2)。但它只是其中一个——所有解是：

x = (0.6, 1.2) + t·(2, −1)

代进去验算：A·(0.6 + 2t, 1.2 − t) = (0.6 + 2t) + 2(1.2 − t) 的第一行 = 0.6 + 2t + 2.4 − 2t = 3 ✓，第二行同理 = 6 ✓。t 取任何值都成立。向量 (2, −1) 就是「被压没了的方向」——它满足 A·n = 0，叫零空间。

再试 b = (3, 7)：(3, 7) 不在那条线上（因为 7 ≠ 2×3），所以无解。这时 solve 报错，lstsq 给你最接近的那一点：投影到 (3.4, 6.8)，残差 (−0.4, 0.2)，长度 0.4472。

一句话记法：解 = 特解 + 零空间的任意组合。
齐次方程 Ax = 0 永远有解（把 x 全取 0 就行）；所以「解不唯一」永远来自「零空间不只有 0」。

注意 lstsq 的「最小范数」：当有无穷多解时，它给你所有解里长度最小的那个。所以上面对 b = (3, 6)，它返回 (0.6, 1.2) 而不是别的。

6动手：10 分钟，用 numpy 验证

# 1. 满秩：有唯一解
import numpy as np
A = np.array([[1, 2], [3, 4]])
print(np.linalg.det(A))                 # -2.0
print(np.linalg.solve(A, [5, 11]))     # [1. 2.]

# 2. 亏秩：两列成比例
B = np.array([[1, 2], [2, 4]])
print(np.linalg.det(B))                 # 0.0
print(np.linalg.matrix_rank(B))         # 1

# 3. 这个 b 在列空间里吗？
for b in ([3, 6], [3, 7]):
    x, res, rank, _ = np.linalg.lstsq(B, b, rcond=None)
    r = np.array(b) - B @ x
    print(b, "解", x, "投影", B @ x, "残差长度", round(float(np.linalg.norm(r)), 4))

# 4. 零空间：找一个 A·n = 0 的 n
n = np.array([2, -1])
print(B @ n)                            # [0. 0.]

# 5. 近乎平行：det 很小但非 0，看条件数
C = np.array([[1, 1], [1, 1.0001]])
print(np.linalg.cond(C))                # 约 40002 —— 病态

跑完做三件事（比读代码重要）：

① 把第 3 段里的 [3, 7] 改成 [3, 6]，看残差长度从 0.4472 变成 0——残差为 0 就是「有精确解」的数值判据。
② 把 B 改成 [[1, 2], [1, 2.0001]]，看 matrix_rank 还是 2，但 condition number 炸了——秩说「够」，条件数说「勉强够」。
③ 打印 B @ np.array([2, -1])，确认零空间方向真的被压成 0。

7练习：三道，做完对答案

1方程组 x + 2y = 3、2x + 4y = 7。先判断有没有解，再算秩，最后求最小二乘解与残差长度。
第二行是不是第一行的整数倍？差在哪？
对答案
无解。 第二式 = 2×第一式，但右边 7 ≠ 2×3 = 6——两条平行线，不重合，所以没有交点。 矩阵 [[1, 2], [2, 4]] 的 det = 0，秩 = 1（列空间是一条线）。 最小二乘解 x ≈ (0.68, 1.36)，投影 (3.4, 6.8)，残差 (−0.4, 0.2)，长度 0.4472。 注意 a·b/(a·a) = (3+14)/5 = 3.4，所以投影是 3.4×(1, 2) = (3.4, 6.8)——和下一课的投影公式提前对上了。
2A = [[1, 2, 3], [2, 4, 6], [1, 1, 1]]。它的秩是多少？Ax = 0 的解空间是几维？写出一个非零解。
第二行是第一行的 2 倍，这一行白占位置。
对答案
秩 = 2（3 行里只有 2 行独立）。 解空间维数 = 未知数个数 − 秩 = 3 − 2 = 1，所以是一条线。 非零解 n = (1, −2, 1)。 验算：1 − 4 + 3 = 0；2 − 8 + 6 = 0；1 − 2 + 1 = 0 ✓。任何 t·(1, −2, 1) 都是解。
3（编程）四点 (0,1)、(1,2)、(2,2)、(3,4) 拟合一条直线 y = w₀ + w₁x。用 lstsq 求 w，并报残差长度。这四个点在同一条直线上吗？
构造 A = 每行 [1, x]，b = 每行的 y。
对答案
w ≈ (0.9, 0.9)，即 y ≈ 0.9 + 0.9x，残差长度 ≈ 0.8367。 不在同一条线上——如果是，残差长度会是 0。所以这个方程组 无精确解，lstsq 求的是最近的那条线。 这就是线性回归的雏形：4 个方程、2 个未知数，超定系统（方程比未知数多），几乎注定无解，于是退而求最小二乘。

明日问题（带着它睡）

刚才 b = (3, 7) 落不到列空间里，我们「投影」进去了。可是投影点是怎么算出来的？为什么在无穷多条候选直线里，垂着落下去的那一条最好？——这就是最小二乘，也是整条路线里线代和微积分第一次握手。

收尾：合上这一页，先自己答这四问，再回看。
  1. 秩的三种说法分别是什么？为什么它们等价？
  2. det = 0 时，方程组为什么只可能是「无解」或「无穷多解」，不能是「唯一解」？
  3. 为什么齐次方程 Ax = 0 永远有解？「解不唯一」的真正原因是什么？
  4. 「没有精确解」和「病态但勉强可解」，是同一件事吗？各用什么数判断？
对答案
1. 独立列数 = 列空间维数 = 消元后非零行数。三者都在数「这个矩阵真正提供几个独立方向」——一列/一行能由其他列/行拼出来，它就不贡献新方向，消元时会被消成 0。 2×2 时等价于 det 是否为 0。 2. det = 0 说明变换把方向压没了，两列共线，列空间从整个平面塌成一条线。b 要么正好在那条线上（此时有无穷多个系数能拼出它），要么不在（怎么拼都拼不出来）。中间那个「恰好唯一」的落脚点已经被压掉了，所以不存在唯一解。 3. x = 0 代入永远成立——零空间至少含原点。所以「唯一解」的意思只是「零空间只有一个点」；一旦零空间里还有别的向量 n，x_p + t·n 就全是解，解集必然放大成一条线（或整个子空间）。 4. 不是。前者是结构问题：b 不在列空间里，数学上就没有精确答案，用秩 / 残差长度判断；后者是数值问题：解存在且唯一，但两列几乎平行，输入的微小误差会被放大几万倍，用条件数 np.linalg.cond 判断。 一句话：秩不够是「没答案」，条件数爆炸是「有答案但别信」。两者都会让 solve 的结果难看，但原因完全不同。
