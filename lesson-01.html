向量：一条数据长什么样

这一课只解决一件事——「这两个东西有多像」怎么用数学回答。它是推荐、搜索、人脸识别的共同起点。

学完你能：把一条数据写成向量；解释内积就是「投影」；说出余弦相似度为什么比欧氏距离更适合做「像不像」的判据；用 numpy 算出来。

1先从一个真实问题开始

你在网易云音乐里点开一首歌，它下面推荐了五首。它怎么知道哪五首「像」？

最朴素的做法是给人打分：一首歌的「节奏快慢」「情绪明亮度」「人声多少」各打 1–10 分。于是每首歌变成了三个数字：

晴天 = (3, 7, 8)　　Shape of You = (8, 6, 9)　　大悲咒 = (1, 2, 9)

有了数字，问题就变成：怎么比较三组数字的「像」？

这里你其实已经做完了最重要的一步——把世界翻译成数字。向量，就是这组数字的名字。

一句定义，但请先别背：向量就是一串有序的数，每个位置叫一个维度，每个维度是一个特征。一条数据 = 一个向量。

2直觉：向量是空间里的一支箭

三个数字听不出「像不像」，但如果你把它当成空间里的一个点——从原点出发，用一支箭指过去——事情立刻变直观。

两首歌「像」，就是两支箭朝同一个方向。下面这张图你可以拖：左边的箭头固定不动，拖动滑块改变「另一首歌」的方向。

θ = 40° cos θ = 0.766 投影 = 1.53 比较像
a 是「数据 A」的方向与长度；b 是「数据 B」。虚线是 a 在 b 方向上的影子（投影）——投影为正时红色，为负时反向、变紫。

看懂这张图，你就懂了内积

把 a 朝 b 的方向「照」过去，会在地上留下一个影子。影子的长度是：

影子长度 = |a| · cos θ

而 b 的长度乘以这个影子，就是内积：

a · b = |a| · |b| · cos θ

换个说法：内积在衡量「a 有多少成分落在 b 的方向上」。两根箭头几乎重合，内积最大；相互垂直，内积为 0——一点关系都没有；方向相反，内积为负。

这也解释了内积为什么是「对应位置相乘再相加」：只有同方向的分量才会互相「对上」，对不上的就浪费了。

a · b = a1b1 + a2b2 + … + anbn

3内积在物理世界里到底算什么

先记住一句话，下面三件事都在重复它：

内积 = 「一个东西在另一个东西的方向上有多少」×「另一个东西有多大」。

场景一：斜着推箱子 —— 做功

你推一个箱子沿地面滑了 5 米，用了 10 牛的力，但手是斜向上的，和地面成 60°。物理课本说做功：

W = 10 × 5 × cos 60° = 25 焦

为什么不是 50 焦？因为你有一半的力在提箱子，只有 F·cos θ = 5 牛 在推它往前走。垂直方向的分力不参与位移，一点功都不做。

斜着推箱子：只有沿位移方向的分量 F·cosθ 在「推」，垂直分量只在「提」。

物理课本写的就是内积：

W = F · s

这就给了「垂直时内积为 0」一个扎扎实实的含义：两个量没有共享的方向，它们之间不发生任何耦合——你提着箱子走，提的力不帮你前进。

场景二：算总成绩 —— 加权求和

数学 90 分、英语 60 分；权重分别是 0.7 和 0.3。总分是：

0.7 × 90 + 0.3 × 60 = 81

注意一件小事：0.7 只能乘数学，管不到英语。每一维是一个独立通道，只有同一通道里的数才互相作用。这就是「逐项相乘再相加」这个定义的来源——它不是数学家拍脑袋规定的，而是「每一维各算各的，最后汇总」这件事的写法。

把权重写成向量 (0.7, 0.3)，成绩写成向量 (90, 60)，总分就是它们的点积。所以：内积 = 加权求和。

场景三：雷达找目标 —— 匹配

雷达发出一个已知波形 s，接收到的回波 r 里混着噪声。怎么判断回波里有没有目标？把 r 和 s 做内积：

有目标时 r ≈ αs + 噪声，r·s 很大；只有噪声时，r·s 在 0 附近随机晃。这就是「匹配滤波」——内积越大，两个信号越对得上。

这条线索一直通到应用层：神经元 = 权重·输入 + 偏置，权重向量的方向就是它最敏感的模式；Transformer 里的 attention 分数，正是 query 和 key 的内积。

四个视角，同一件事

视角内积在算什么
几何a 在 b 上的投影长度 × b 的长度
物理力沿位移方向做的功
代数逐维相乘再相加 = 加权求和
工程两个信号的匹配 / 相关程度

真正该记住的不是公式，而是这句：内积在度量「两个东西在彼此方向上的交集，乘以各自有多大」。

一个反例：内积大 ≠ 相似

(100, 0) 和 (1, 0) 的内积是 100，很大。可这两支箭的方向其实完全一样，只是长度差了 99 倍——按下一节的说法，它们是「同一个口味、不同的活跃度」。

这个例子暴露的正是问题所在：内积把「方向」和「长度」乘在了一起，你没法从 100 这个数里读出，到底是方向对上了，还是只因为向量长。

换两组数看得更清楚（数字都核过）：

对比内积余弦实际关系
(10, 0) 和 (1, 1)100.71夹 45°，不像
(0.5, 0.5) 和 (0.5, 0.5)0.51.00同一个东西
(100, 0, 0) 和 (0.3, 1, 0)300.29几乎垂直
(1, 0, 0) 和 (0.99, 0.1, 0)0.990.995几乎重合

前两行：内积判「10 比 0.5 大得多」，可方向差得远的那对，内积反而更大。后两行更狠——内积大的那对更不像。而且内积不能跨对比较：两对的长度都不一样，比出来的往往只是「谁更长」。

所以正确的分工是：

你要回答的用哪个它在算什么
对得上多少／耦合多强a · ba 在 b 方向的影子 × b 的长度
像不像a·b / (|a||b|)只留方向，取值范围 −1 到 1
数据里结构像不像中心化余弦（≈ 皮尔逊相关）先减掉各自的均值，去掉共同基线
差多少|a − b|距离，含长度

那内积为什么还是一号主角？因为「吃两个向量、吐一个数」的基本运算就是它：固定 b 之后，它对 a 是一次线性打分，等价于加权求和。神经元 w·x + b、attention 的 q·k、最小二乘的 XTX，骨架都是它。它更像一个底层动作，余弦是它抹掉长度之后的特例。

顺带一个坑：attention 里用的是原始内积、只除以 √d，不换成余弦——因为长度本身携带信息（词频、置信度），一刀切掉会丢东西。

一句话：内积告诉你「对上了多少」，不告诉你「像不像」。要问像不像，先除以两个长度。

4为什么是余弦，不是距离

你可能会问：直接量两个点的直线距离不行吗？行，但有个坑。

设想两个用户看电影：

用户科幻片爱情片看片量
A1 部1 部2
B10 部10 部20

两人的口味比例完全一样（科幻与爱情各占一半），只是 B 看得多。可是欧氏距离算出来是：

|A − B| = √(9² + 9²) ≈ 12.7

距离很大，算法会判定「这两个人不像」。可他们的偏好明明一样。

问题出在长度上：长度里混进了「活跃度」这个信息。而余弦相似度把长度除掉了，只看方向：

cos(A, B) = (A·B) / (|A|·|B|) = 1

完全同向，相似度 1，判对了。

记住这个分工：长度代表「程度／活跃度／量级」，方向代表「结构／偏好／类型」。
问「像不像」→ 看方向（余弦）。问「差多少」→ 看距离（欧氏）。

5工具表：这一课只留四个式子

名字式子什么时候用
向量a = (a1, a2, …, an)一条数据、一个样本、一个 embedding
长度（模）|a| = √(a1² + … + an²)量级、归一化
内积a · b = Σ aibi = |a||b|cos θ投影、相似度、线性组合
余弦相似度cos θ = (a·b) / (|a||b|)推荐、检索、文本相似——取值范围 −1 到 1

余弦为 1：完全同向 · 0：垂直、无关 · −1：完全相反。现实中的 embedding 相似度通常落在 0.2–0.9，0.8 以上已经算「很像」。

6手算一遍，别跳

用开头那三首歌的数字，算「晴天」和「Shape of You」：

a = (3, 7, 8)　　b = (8, 6, 9)

第一步，内积：3×8 + 7×6 + 8×9 = 24 + 42 + 72 = 138

第二步，长度：|a| = √(9+49+64) = √122 ≈ 11.05；|b| = √(64+36+81) = √181 ≈ 13.45

第三步，余弦：138 ÷ (11.05 × 13.45) = 138 ÷ 148.6 ≈ 0.93

0.93，方向高度一致，两首歌确实「像」。再算「晴天」和「大悲咒」(1, 2, 9)：内积 = 3+14+72 = 89，|c| = √(1+4+81)=√86≈9.27，cos = 89 ÷ (11.05×9.27) ≈ 0.87。

咦，也 0.87？因为三个特征全是正分，两个向量都整体偏高——这叫共同基线，它会把余弦一起抬上去。真实系统用几千维特征就是为了避免这种粗糙。这也说明：特征的选取决定了「像」的定义——这是建模里最值钱的一步。

验证一下：把每个向量减去自己的均值（只平移，不改形状）再算余弦——晴天·大悲咒从 0.87 掉到 0.74，晴天·Shape of You 从 0.93 掉到 0.00。后一个数说明：它俩的「像」几乎全部来自「三科都不低」这个共同基线。三维太少，别把这个具体数字当结论，当成警报即可——问结构像不像之前，先问「基线去掉了没有」。皮尔逊相关干的就是这件事。

7动手：10 分钟，用 numpy 算

打开终端，进 python3，逐行敲（别复制一整段，一行一行来，看每行的输出）：

# 1. 把两条数据写成向量
import numpy as np
a = np.array([3, 7, 8])      # 晴天
b = np.array([8, 6, 9])      # Shape of You

# 2. 内积：@ 就是点积
print(a @ b)                # 138

# 3. 长度
print(np.linalg.norm(a))    # 11.045…

# 4. 余弦相似度
cos = (a @ b) / (np.linalg.norm(a) * np.linalg.norm(b))
print(cos)                  # 0.9283…

然后做三件事（这一步比看代码重要）：

① 把 b 改成 [16, 12, 18]（所有数乘 2），再算 cos——结果变了吗？
② 把 b 改成 [9, 7, 3]（顺序反过来），cos 变成多少？
③ 把 b 改成 [-3, -7, -8]，cos 是多少？为什么？

你应该发现：① 长度翻倍，余弦不变（方向没变）；② 换了顺序，相似度掉下来（位置即特征，错位就没法比）；③ 完全相反，约等于 −1。
这三条就是「向量是有序的」和「余弦只看方向」的直接证据。

8练习：三道，做完对答案

1a = (2, 0)，b = (1, √3)。求内积、|a|、|b|、夹角余弦。

可以只用内积那一条式子，也可以用几何直觉（b 的方向是 60°）。

对答案
a·b = 2×1 + 0×√3 = 2；|a| = 2；|b| = √(1+3) = 2。 cos = 2/(2×2) = 0.5，所以 θ = 60°。和「b 在 60° 方向」的直觉一致。
2用户 A 评分 (1, 1)，用户 B 评分 (10, 10)。分别算欧氏距离和余弦相似度，然后回答：推荐系统该用哪个？为什么？
对答案
距离 = √(81+81) ≈ 12.7；余弦 = (10+10)/(√2·√200) = 20/20 = 1。 用余弦。两人口味结构完全相同，只是活跃度不同；用距离会把「活跃」误判成「不像」。若确实想区分活跃度，应该把长度作为单独的一维特征，而不是塞进相似度里。
3（编程）把下面三个「句子向量」两两算余弦，找出与第 1 句最像的：
s1 = np.array([0.2, 0.8, 0.1, 0.5])
s2 = np.array([0.1, 0.9, 0.0, 0.6])
s3 = np.array([0.7, 0.1, 0.9, 0.2])

先猜再算——猜错的地方就是你直觉还没长好的地方。

对答案
cos(s1,s2) ≈ 0.987；cos(s1,s3) ≈ 0.364；cos(s2,s3) ≈ 0.222。 s1 与 s2 最像。注意：这两个向量长度不同，但方向很近——这就是「只看方向」的好处。
